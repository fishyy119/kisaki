# i18n System

Kisaki ships a custom, zero-dependency, fully typed i18n system. UI copy lives in TypeScript
message catalogs under `apps/desktop/src/shared/i18n/messages/`; locale-aware value display goes
through `Intl`-based formatters. Supported UI locales: `en`, `ja`, `zh-Hans`, `zh-Hant`.

## Key Files

- `apps/desktop/src/shared/i18n/locales.ts` - `UiLocale`, `ContentLocale`, `UiLocaleState`, parsers
- `apps/desktop/src/shared/i18n/negotiation.ts` - system language negotiation (`resolveUiLocale`)
- `apps/desktop/src/shared/i18n/formatting.ts` - `createFormatters` (`Intl` date/duration/number)
- `apps/desktop/src/shared/i18n/messages/` - message catalogs (`en` is the schema source)
- `apps/desktop/src/main/services/i18n/` - main-process `I18nService` (preference owner)
- `apps/desktop/src/renderer/src/core/i18n/` - renderer mirror (reactive locale/messages/formatters)
- `apps/desktop/src/renderer/src/composables/use-i18n.ts` - `useI18n()` composable
- `packages/extension-api/src/shared/locales.ts` - protocol-side `UiLocale`, `ContentLocale`,
  `LocalizedText`, `resolveLocalizedText`

## Core Concepts

### UiLocale vs ContentLocale

- `UiLocale` (`en | ja | zh-Hans | zh-Hant`) is the interface language. It drives message catalogs
  and formatters.
- `ContentLocale` is the media metadata language (scraper lookups, manifest content), a wider set.
- The app (`@shared/i18n`) and the extension protocol (`@kisaki3/extension-api`) declare these
  types independently on purpose (dual ownership). They are structurally identical, so values flow
  across the boundary without imports from app to protocol. Never re-export one side from the other.

### Locale State Ownership

The main-process `I18nService` owns the UI locale preference:

- `settings.ui_locale` column persists the preference; `null` means follow the system language.
- Effective locale = preference, or `resolveUiLocale(app.getPreferredSystemLanguages())`.
- Renderer reads state via `i18n:get-state`, writes via `i18n:set-preference`, and follows
  `app.ui-locale.changed` events (payload `{ preference, effective }`).
- Traditional Chinese negotiation: `zh-TW` / `zh-HK` / `zh-MO` and explicit `zh-Hant` map to
  `zh-Hant`; other `zh` tags map to `zh-Hans`.

### Message Catalogs

- `messages/en/` is the schema source. `messages/schema.ts` derives `type Messages = typeof en`.
- Other locales implement each domain with `satisfies Messages['<domain>']`, so missing or extra
  keys fail typecheck.
- One file per domain (`settings.ts`, `library.ts`, ...). Domain indexes aggregate into the locale
  catalog; `messages/index.ts` exports `MESSAGE_CATALOGS` and `getMessages(locale)`.
- Cross-feature vocabulary is split by what it is, never into a catch-all: `actions` (button and
  menu verbs), `states` (loading, toggles, presence words), `feedback` (generic outcome toasts),
  `sorting` (sort control words), `values` (placeholders, empty states, count formats). Feature copy
  stays in its own domain; a new generic string joins the domain that names its kind.
- Parameterized messages are plain arrow functions: `itemCount: ({ count }) => ...`. No runtime
  interpolation engine and no external i18n library.

### Renderer Usage

```vue
<script setup lang="ts">
import { useI18n } from '@renderer/composables/use-i18n'

const { m, f, locale, preference, setPreference } = useI18n()
</script>

<template>
  <Button>{{ m.actions.save }}</Button>
  <span>{{ f.date(game.releaseDate) }}</span>
  <span>{{ game.totalDuration > 0 ? f.duration(game.totalDuration) : m.values.emptyValue }}</span>
</template>
```

- `m` and `f` are `ComputedRef`s: use `m.value...` in script, auto-unwrapped in templates.
- Plain TS modules (non-component) import the reactive singletons directly:
  `import { messages, formatters, uiLocale } from '@renderer/core/i18n'`.
- Callers decide empty-state rendering; formatters accept non-null values only.

### Formatters

`createFormatters(locale)` returns cached `Intl` formatters: `date` (accepts `PartialDate`),
`dateTime`, `time`, `dateRange`, `monthDayRange`, `yearMonth`, `dateTimeRange`, `relativeTime`,
`duration` (hours/minutes), `durationFine` (seconds/ms precision), `durationCompact`, `number`,
`percent`, `monthName`, `languageName`. Language pickers use `languageAutonym(tag)` so each option
renders in its own language.

Never hardcode a locale (`toLocaleString('zh-Hans')`, `new Intl.DateTimeFormat('zh-CN')`) in
display code. Pure calendar math and HTML input formatting stay in `@renderer/utils/datetime`.

### Main Process Usage

`I18nService` exposes `service.locale` (effective `UiLocale`), `service.messages`, and
`service.formatters` for main-owned user-visible strings (tray menu, native notifications, task
snapshot labels). Snapshots rendered at execution time use the locale current at that moment.

### Extensions

- Manifest `name` / `description` (and registry `name` / `summary` / `description`) accept
  `LocalizedText`: either a plain string or `{ en: '...', 'zh-Hans': '...' }` with `en` required.
- Hosts pass `LocalizedText` through DTOs untouched; the renderer resolves it against the current
  UI locale via `resolveExtensionText` (`@renderer/core/extensions`). Main-process logs, sorting
  baselines, and runtime metadata resolve with the `en` baseline.
- Extensions receive the UI locale via `RuntimeInfo.uiLocale` and the `app.ui-locale.changed` host
  event, and own their runtime translations.

## Copy Style Guide

### Keys

- English camelCase, grouped by domain namespace (`m.settings.language.followSystem`).
- Name the role, not the content: `deleteConfirmTitle`, not `areYouSureDelete`.
- Keep keys stable; renaming a key is a refactor across all four catalogs.

### Punctuation

A period separates one sentence from the next. UI copy owns its slot - a label, a
description, a toast - so the slot already ends the thought and a trailing period only
adds noise. One rule covers every catalog entry:

**A single-sentence message takes no final period. A message of two or more sentences
punctuates all of them, final one included.**

```ts
saved: 'Saved',                                       // single sentence
loadFailed: 'Failed to load settings',                // single sentence
deleteDescription: 'Delete this record? This cannot be undone.'  // two sentences
```

`?`, `!`, and `…` carry meaning (a question, an ongoing state, a follow-up surface) and
are always kept, including at the end of a single-sentence message (`Remove "X"?`,
`Loading…`, `Browse…`). An abbreviation's own dot is not a sentence end (`e.g. D:\Games`
stays one sentence). The rule is locale-independent: `。` follows it exactly as `.` does.

It applies to catalog copy only. Errors thrown in the main process are diagnostic prose,
not UI slots, and keep their periods (`Failed to install extension package.`); so does
long-form Markdown such as changelog bodies.

### Labels And Titles

- Noun phrases.
- English uses sentence case (`Interface language`, not `Interface Language`).

### Buttons And Menu Items

- Short verb or verb-object phrases: `Save`, `Check for updates`, `保存`, `更新を確認`.
- No ellipsis unless the action opens a follow-up surface (`Browse…`).

### Placeholders

Exactly three allowed forms:

1. Search hint (`Search games`).
2. Format example (`e.g. D:\Games`, `例如：D:\Games`).
3. Omitted entirely.

Never repeat the field label and never use polite filler (`请输入…` / `Please enter…`).

### Feedback And Descriptions

- Keep toast titles short and reuse the generic `feedback` vocabulary (`m.feedback.saved`,
  `m.feedback.saveFailed`).
- User-facing error strings thrown from main stay English and stable; the renderer owns localized
  presentation.

### Language-Specific Rules

- `zh-Hans` / `zh-Hant`: full-width punctuation（，。：）; no space between CJK and inline Latin
  identifiers is required by CJK typography defaults; keep both variants written natively, not
  machine-converted (`设置/設定`, `扩展/擴充功能`).
- `ja`: prefer 漢語 nouns for labels (`設定`, `表示言語`) and です/ます style for sentences.
- `en`: sentence case everywhere except product names.

## Adding A Message

1. Add the key to the matching domain file in `messages/en/` (create the domain file and register
   it in every locale index if new).
2. Add translations to `zh-hans/`, `zh-hant/`, and `ja/`; `satisfies` enforces completeness.
3. Use it via `m.<domain>.<key>` in the renderer or `service.messages` in main.

## Constraints

- No CJK literals outside `messages/zh-hans`, `messages/zh-hant`, and `messages/ja`.
- No bare text in Vue templates; render through `m` or component props fed by `m`.
- Do not hardcode locales in `Intl` constructors or `toLocale*` calls in display code.
- Do not use Chinese strings as message keys.
- `shared/i18n` stays pure: no process APIs, no reactive state.
